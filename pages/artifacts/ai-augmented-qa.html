AI-Augmented QA Workflow

Real workflow, from an actual project

I use AI coding agents (Claude Code) as part of my QA and automation practice, not to replace test design or judgment, but to accelerate implementation while I own the strategy, review every change, and verify every claim before it ships. This page walks through a real example.

My working principles

  • I always review the diff before any commit. I don't accept AI-generated changes blind.
  • I ask the agent to inspect real code and logs before writing anything, instead of letting it assume.
  • I verify claims against live evidence (a passing pipeline, a rendered page, a query result) rather than trusting a description of success.
  • I keep commits scoped and reversible, and I never let an agent push to a live/production branch without my explicit confirmation.
  • Commit messages and authorship stay mine, no co-author trailers, no "generated with" tags.

Real example: diagnosing a CI/CD pipeline failure

I added a GitHub Actions workflow to a Playwright E2E test suite to publish the HTML test report and a live test plan/bug registry to GitHub Pages after every run.

The first attempt failed: the publish step returned a 403 error, remote: Permission to [repo] denied to github-actions[bot], because the default GITHUB_TOKEN lacked write access to push the gh-pages branch.

I reviewed the actual Actions log to find the root cause rather than guessing, then added a minimal permissions: contents: write block scoped only to the job that needed it, and checked the diff before committing.

Once publishing succeeded, a second issue turned up: the root URL landed on a page with two links instead of going straight to the most relevant one, the test plan. I adjusted the generated index.html to redirect directly, again reviewing the exact diff before pushing.

After each change I confirmed the live URLs actually worked in the browser, rather than assuming success from the tool's own report.

The outcome is a working CI pipeline that runs the suite on every push, fails on any test failure, and publishes a live, browsable test report and bug registry: live report · repository.

Where I draw the line

AI accelerates the mechanical parts: writing YAML, generating boilerplate, drafting documentation. But test strategy, risk analysis, what to automate vs. not, and sign-off on what actually ships are mine. Every automated suite and CI pipeline in this portfolio was built this way: agent-assisted, human-verified.
